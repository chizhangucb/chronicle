# 自動同期

Chronicle はバックグラウンドで自身を最新に保ちます。新規および更新されたセッションは自動的に再インポートされるため、Sync をクリックしなくても、アプリは AI ツールの動きをそのまま反映します。

手動インポートも引き続き利用できます（ウィザード、セッションごとの `⇧⌘U`、プロジェクトごとの同期）が、自動同期を有効にしていれば日常的には不要なはずです。トレイアプリがツールのログディレクトリを監視し、変更のあったものをすべて再インポートします——増分的に、読み取り専用で、そして完全にあなたのマシン上で。

## 同期のトリガー

自動同期は**増分的**です。1 回のパスでは、ソースファイルの mtime が前回のインポートより新しいセッションだけを再インポートします。新しいデータが現れる経路を、4 つのトリガーでカバーします。

| トリガー | 存在する理由 |
| --- | --- |
| **起動時** | Chronicle が動いていなかった間に起きたことをすべて拾うため |
| **システムのスリープ復帰時** | macOS はスリープをまたぐとファイルシステム監視イベントを取りこぼします——スリープからの復帰は監視が古くなる主な原因なので、復帰時に強制的にパスを実行します |
| **30 分ごと** | 監視イベントを取りこぼした場合に備えたバックストップのタイマー |
| **ファイルシステム監視** | 既知のソースディレクトリを監視し、変更があれば同期をスケジュールします。**最後の書き込みから約 30 秒のデバウンス**が入るため、ストリーミング中のセッションが 1 行ごとに再インポートされることはありません |

再インポートは `replaceSession`——冪等な削除と再挿入——なので、進行中のセッションを同期しても安全です。途中までのインポートは、単に次のパスで上書きされるだけです。あなたが付けた名前（`name`）はどの同期でも保持され、ソースログに書き込まれることは決してありません。

## 設定

**Settings** に 2 つのトグルがあります。

- **Auto-sync** — 仕組み全体のオン・オフを切り替えます。オフにすると、Chronicle は明示的に指示したときだけインポートします。
- **Launch at login** — ログイン時に Chronicle を（トレイで）起動し、ウィンドウを開いたときにセッションが常に最新の状態になるようにします。

ウィンドウを閉じると Chronicle はトレイに隠れ、自動同期はそこで動き続けます。完全に停止するにはトレイメニューから終了してください。

## 「進行中」インジケーター

ソースファイルが直近 **10 分**以内に書き込まれたセッションは、**進行中（ongoing）**として表示されます。セッションにアクティブインジケーターが付き、統計には「so far」というラベルが添えられます——カウントと所要時間は、まだ書き込み中のセッションのスナップショットであり、次の同期パスで更新されます。

自動同期の目的は**永続性**（データベースが自力で追いつくこと）です。アクティブなセッションをメッセージ単位で本当にリアルタイムに追尾するには、[ライブストリーミング](./live-streaming.md)を使ってください——そちらが引き続きライブネスのビューです。

## ディープリンク

Chronicle は `chronicle://` URL スキームを登録します。

```
chronicle://session/<id>
```

を開くと、アプリにフォーカスが移り（起動していなければ起動し）、そのセッションへ直接ナビゲートします。Chronicle のセッション id を知っている外部ツール——ダッシュボード、スクリプト、メモ——なら何でも、セッションビューへ直接リンクできます。
