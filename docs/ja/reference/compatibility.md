# 互換性

Chronicle がサポートする AI コーディングツール、ツールごとに各機能が何を行うか、そして各ツールのログがディスク上のどこに置かれているかを示します。

Chronicle は 6 つのツールから会話ログをインポートし、すべてのメッセージをその時点の Git スナップショットにマッピングします。ほとんどの機能は 6 つすべてで同じように動作します。サブエージェント（サイドチェーン）の帰属は Claude Code 固有で、リモートアクセスはまだ実装されていません。以下の内容はすべて v0.2.0 で提供されるものを反映しています。さらに詳しく知りたい場合は、ソースキーを `server/parsers/<tool>.js` と照らし合わせて確認してください。

| タイムトラベル／コードスナップショット | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| Replay モード | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| メッセージのフィルタリング | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| コンテンツの秘匿化 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| ツール呼び出しの表示 | ✅ | ✅ | ✅ | ✅ | ⚠️ | ✅ |
| コンテキスト因果関係 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| Git 履歴とのマッチング | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| ライブストリーミング | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| 自動同期 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| サイドチェーン（サブエージェント）のインポート | ✅ | – | – | – | – | – |
| メッセージ単位のトークン使用量 | ✅ | ⚠️ | ⚠️ | ⚠️ | ⚠️ | ⚠️ |

凡例: ✅ 完全対応 · ⚠️ 部分対応 · 🔜 計画中（未実装） · – 対象外。

- **ツール呼び出しの表示**は Gemini CLI では部分対応です。そのログは、JSONL ベースのツールに比べてツールの活動の記録が不完全です。
- **サイドチェーン（サブエージェント）のインポート** — `agent_type` と `skill` の帰属付き — は Claude Code の概念です。他のパーサーはすべての行を `is_sidechain = 0` としてマークします。
- **メッセージ単位のトークン使用量**は、ツールのログに使用量レコードが含まれている場合に取得されます。カバレッジはツールとログのバージョンによって異なります。[メトリクスとコントラクトビュー](../architecture/metrics-and-contract.md)を参照してください。
- **リモート SSH アクセス**（SSH 越しのインポート／閲覧／ライブ監視）は、どのツールについても**計画中で未実装**です。Chronicle が現在行うことはすべてローカルファイルに対して動作します。

## ログの場所

各パーサーは、そのツールのネイティブなログを既知のパスから読み取ります。Chronicle がこれらに書き込むことはありません。読み取り専用の列を参照してください。

| ツール | ソースキー | パス | 形式 | 読み取り専用の扱い |
| --- | --- | --- | --- | --- |
| Claude Code | `claude-code` | `~/.claude/projects/` | JSONL | その場で読み取り。原本は変更されない |
| Codex | `codex` | `~/.codex/sessions/` | JSONL | その場で読み取り。原本は変更されない |
| Cursor | `cursor` | VS Code `workspaceStorage` の state DB（`CHRONICLE_CURSOR_DIR` で上書き可） | SQLite（WAL） | **`-wal`/`-shm` を含めて**一時領域へコピーしてから開く |
| OpenCode | `opencode` | `~/.local/share/opencode/opencode.db` | SQLite（WAL） | **`-wal`/`-shm` を含めて**一時領域へコピーしてから開く |
| Gemini CLI | `gemini-cli` | `~/.gemini/tmp/` | JSON | その場で読み取り。原本は変更されない |
| Copilot Chat | `copilot-chat` | VS Code `workspaceStorage/<hash>/chatSessions/`（`CHRONICLE_VSCODE_DIR` で上書き可） | JSON | その場で読み取り。原本は変更されない |

> **常に読み取り専用:** SQLite ベースのソース（Cursor、OpenCode）は WAL データベースです。`.db` ファイルだけをコピーすると*空の*データベースになります — 直近の書き込みは `-wal` サイドカーにあるためです。そこでパーサーは `-wal` と `-shm` ファイルも一時領域へコピーし、そのコピーを開きます。ツールの稼働中のデータベースに触れることは決してありません。

デフォルトのパス定数は各パーサー内にあります（`server/parsers/*.js` の `CLAUDE_PROJECTS_DIR`、`CODEX_SESSIONS_DIR`、`OPENCODE_DB`、`GEMINI_TMP`）。環境変数による上書きを公開しているのは Cursor と Copilot のみです。[設定](./configuration.md)を参照してください。

### ツールごとの注意点

- **Gemini CLI は作業ディレクトリを記録しません。** ログに `cwd` がないため、Chronicle は仮想パス（`gemini-project:<hash>`）を割り当て、**「Needs association（関連付けが必要）」**バナーを表示します。一度実際のプロジェクトに向ければ、Chronicle はパスの一致によってセッションをマージします。
- **Copilot Chat は複数の VS Code ディストリビューションにまたがります。** スキャナーは VS Code の **stable、Insiders、VSCodium** の `workspaceStorage` を参照するため、どのインストールの Copilot セッションでも検出されます。
- **Cursor と OpenCode は 1 つのデータベースを複数のセッションで共有します。** 1 つのファイルが多くのセッションを支えているため、これらのツールではセッション単位のソースファイル削除は無効化されています（1 ファイル＝1 セッションのソースである Claude Code、Codex、Copilot でのみ提供されます）。

## 既知の制限

- **大規模なセッションは緩やかに縮退します。** 約 5,000 メッセージを超えると、UI はウィンドウ化レンダリングに切り替わります。現在位置の周囲およそ 400 の DOM 行だけを描画し、タイムラインの目盛りを間引くため、6,000 メッセージのセッションでも応答性を保ちます。ナビゲーションは、無制限のスクロールではなく検索とタイムラインで行います。
- **Git サブモジュール**はスナップショットエンジンでサポートされています。
- **標準外またはカスタムのログパス**は手動選択で扱います。インポートウィザードの Browse オプション（または `CHRONICLE_CURSOR_DIR` / `CHRONICLE_VSCODE_DIR` の上書き）を使って、デフォルトの場所の外にあるログを Chronicle に指定してください。
