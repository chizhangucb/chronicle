# 自动同步

Chronicle 会在后台自动保持自身最新：新增和更新的会话会被自动重新导入，因此应用始终反映你的 AI 工具正在做什么，你无需再点击「同步」。

手动导入依然存在（导入向导、按会话的 `⇧⌘U`、按项目同步），但开启自动同步后，日常使用中你应该不再需要它。托盘应用会监视各工具的日志目录，并重新导入任何发生变化的内容——增量、只读，且完全在你的机器上进行。

## 什么会触发一次同步

自动同步是**增量**的：每一轮只重新导入源文件 mtime 比上次导入更新的会话。四种触发方式覆盖了新数据出现的所有途径：

| 触发方式 | 存在的理由 |
| --- | --- |
| **启动时** | 补上 Chronicle 未运行期间发生的一切 |
| **系统唤醒时** | macOS 会在睡眠期间丢失文件系统监视事件——从睡眠中恢复是监视器失效的主要原因，因此唤醒会强制执行一轮同步 |
| **每 30 分钟** | 一个兜底定时器，以防某个监视事件被漏掉 |
| **文件系统监视** | 已知的来源目录会被监视；发生变化时会调度一次同步，**在最后一次写入后防抖约 30 秒**，避免正在流式写入的会话每写一行就被重新导入一次 |

重新导入使用 `replaceSession`——一个幂等的删除后重插——因此同步一个进行中的会话是安全的：不完整的导入只会被下一轮同步覆盖。你的重命名（`name`）在每次同步后都会保留，源日志也永远不会被写入。

## 设置

**设置**中有两个开关：

- **Auto-sync** —— 整体开启或关闭该机制。关闭后 Chronicle 只在你主动要求时才导入。
- **Launch at login** —— 登录时自动启动 Chronicle（在托盘中），这样打开窗口时会话始终是新鲜的。

关闭窗口会将 Chronicle 隐藏到托盘；自动同步在托盘中继续运行。要彻底停止，请从托盘菜单退出。

## 「进行中」指示器

源文件在最近 **10 分钟**内被写入过的会话会显示为**进行中 (ongoing)**：会话上有一个活跃指示器，其统计数据标注为「至今为止 (so far)」——计数和时长只是一个仍在被写入的会话的快照，下一轮同步会更新它们。

自动同步关乎**持久性**（数据库自行追上进度）；若要对活跃会话进行真正实时、逐条消息的跟踪，请使用 [实时流式](./live-streaming.md)——那仍然是实时视图。

## 深度链接

Chronicle 注册了 `chronicle://` URL scheme。打开

```
chronicle://session/<id>
```

会聚焦（或启动）应用并直接跳转到该会话。任何知道 Chronicle 会话 id 的外部工具——一个仪表盘、一个脚本、一条笔记——都可以直接链接进会话视图。
