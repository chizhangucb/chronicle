# 隐私与数据

Chronicle 存储什么、存储在何处，以及那少数几项会离开你机器的内容的完整清单。

Chronicle 在设计上就是本地优先，而非靠配置实现。解析、存储、查看、回放，乃至分享链接的生成，全部在设备上进行，也没有可供"选择退出"的云端后端。本页是一份诚实的说明：各项保证、确切的出站网络调用（一共只有三项，全部由用户发起或为可选项），以及你的数据实际存放的位置。

## 本地优先的保证

- **所有工作都在设备上进行。** 导入、解析、存储、搜索、时间旅行、因果分析、脱敏、回放以及分享页面的构建，全部在你的机器上运行。
- **任何地方都没有 LLM 调用。** 一切看起来像 AI 的东西——因果置信度分级、密钥脱敏、成本计算——都是本地启发式或静态表。Chronicle 从不把你的对话发送给任何模型。
- **没有云端后端，没有账户。** 没有任何需要登录的东西，也没有持有你数据的服务器。
- **你的源日志从不被写入。** Chronicle 只读取你的工具的日志，不修改也不删除它们。基于 SQLite 的来源（Cursor、OpenCode）会被复制到临时位置——包括其 `-wal`/`-shm` 附属文件——Chronicle 打开的是*副本*，从不打开你的实时数据库。
- **你的项目仓库从不被写入。** Git 快照引擎是严格只读的：它调用 `git rev-list`、`ls-tree` 和 `show` 从历史中重建过去的代码状态。它从不提交、检出或暂存任何内容。
- **对外部系统只读。** 同样的只读姿态适用于每个工具的数据——Chronicle 只做观察者。

## 什么会离开机器

默认情况下，Chronicle 在查看或管理你的会话时**不进行任何**网络调用。只存在两个出站调用，且每一个要么是可选的，要么由你显式触发：

1. **更新检查与下载。** 在打包的桌面应用中，`electron-updater` 会轮询公共 `chizhangucb/homebrew-chronicle` tap 的 GitHub release 源，并在后台下载经过公证的新构建。这是标准的应用更新路径；不携带任何会话数据。
2. **反馈（仅在你提交时）。** 提交反馈表单会 POST 到托管在 `relay.getchronicle.dev` 的中继。消息**总是先在本地追加到 `~/.chronicle/feedback.log`**，因此没有任何环节依赖网络；如果中继不可达，UI 会回退为一封 `mailto:` 草稿。发件人邮箱字段是可选的——填写后它会成为回复地址；留空则没有任何信息标识你。

除此之外没有任何内容离开机器。特别是，**会话内容从不为了解析、查看或分析而被传输**——后台[自动同步](../guide/auto-sync.md)也纯粹是本地文件读取，从不进行网络调用。

## 分享链接留在本地

分享链接由**你自己正在运行的 Chronicle** 提供服务，而不是某个托管服务。创建分享时，Chronicle 会存储一份**在创建时刻冻结的脱敏转录副本**，并通过本地的 `/share/:token` 页面提供。原始会话从不被上传，创建之后的编辑也不会改变已存在的分享。你可以在 Share Management 中查看访问次数并立即撤销链接。

## 你的数据在哪里

Chronicle 持久化的一切都在 `~/.chronicle/` 之下（完整布局见[配置](./configuration.md)）：位于 `~/.chronicle/chronicle.db` 的 SQLite 数据库、回放沙箱，以及 `feedback.log`。它们都留在你的磁盘上。

> **脱敏是单向的。** 当 Chronicle 脱敏密钥时——无论是为了分享链接、导出的 Markdown 转录，还是安全扫描——它替换的是敏感文本本身；不会保留可逆的映射。脱敏后的产物无法还原为原文，且过程中你存储的原始内容从不被修改。
